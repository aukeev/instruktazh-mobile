# Инструктаж КарНУ — мобильное приложение инструктирующего

Устанавливаемое веб-приложение (PWA) для проведения инструктажей по БиОТ с телефона.
Записи создаются в том же формате, что и в журнале, и передаются в журнал автоматически через общий сервер (папка `server/`) или, как запасной вариант, файлом .json.

## Как пользоваться
1. Откройте ссылку на приложение в Chrome (Android) или Safari (iPhone) и добавьте на главный экран.
2. ⚙ Настройки: укажите свои ФИО и должность, загрузите штатку (CSV: ФИО; ИИН; Табельный номер; Должность; Подразделение) или архив .json журнала. Задайте PIN.
3. «Новый инструктаж»: подразделение, вид, причина (для внепланового и целевого), инструкции, дата.
4. «Кто присутствует»: отметьте работников, при необходимости добавьте человека вручную.
5. Каждый работник сканирует QR своим eGov Mobile («eGov QR») и подписывает. ФИО и ИИН сверяются с сертификатом; если ИИН не был известен, он берётся из сертификата.
6. Инструктирующий подписывает последним кнопкой «Открыть eGov Mobile» на этом же телефоне. Запись закрыта.
7. Если выполнен вход на общий сервер (⚙ → «Общий сервер журнала»), закрытая запись уходит туда сама; без интернета ждет в очереди. Без сервера: «Выгрузить в файл», файл .json импортируется в журнал. Отправленные записи можно удалить с телефона (Настройки → Очистка).

## Работа по журналам ЭЖИ
Если инженер ОТОС отправил из ЭЖИ на сервер контингент и реестр журналов (ЭЖИ → Настройки → «Телефоны и общий сервер»), телефон получает их сам. Тогда «Новый инструктаж» идет по журналу ЭЖИ: журнал, вид и программа выбираются как в ЭЖИ, работник подписывает тот же текст, что сформировал бы ЭЖИ, а инструктирующий подписывает отдельный документ на каждого работника одним сеансом eGov Mobile. В ЭЖИ такие записи загружаются кнопкой «Загрузить с сервера» без ручного выбора журнала. Отключить: ⚙ → «Журнал ЭЖИ».

## Правила подписи
- Сверка (как в журнале v1.1): `ok` — ИИН совпал; `name` — ИИН не был известен, совпали фамилия и имя (ИИН берётся из сертификата); `warn` — требует ручной сверки; `bad` — ИИН в ЭЦП не совпал (не засчитывается, запись не закрыть). ИИН проверяется по контрольной цифре.
- Повторная подпись не затирает прежнюю: она сохраняется в `worker.sigHistory`.
- Демо-подписи (`sig.demo=true`) закрывают запись только в демо-режиме, запись получает `demo: true`.

## Данные
Записи хранятся на телефоне (localStorage) и, после входа, на общем сервере журнала в облаке РК. На GitHub Pages попадают только файлы программы. Демо-записи на сервер не отправляются.
Подпись идёт через сервис SIGEX (sigex.kz), нужен интернет. Остальное работает без сети.
PIN защищает от случайного просмотра, но не шифрует данные.

## Состав репозитория
- корень: мобильное приложение;
- `journal/index.html`: журнал для компьютера v1.2 (синхронизация с сервером);
- `server/`: сервер журнала, установка и обслуживание описаны в [server/README.md](server/README.md).

## Файлы приложения
`index.html`, `app.js` — приложение; `sigex.js` — клиент SIGEX QR (MIT, © SIGEX); `ezhi.js` — тексты подписи и разбор сертификата в формате ЭЖИ v3.4; `sw.js` — офлайн-кэш; `manifest.webmanifest`, `icon*` — установка.

Для камеры и установки нужен HTTPS (GitHub Pages подходит).
