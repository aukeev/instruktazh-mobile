# Сервер электронного журнала инструктажей

Общее хранилище записей инструктажей и подписей ЭЦП. Телефоны инструктирующих сами отправляют сюда закрытые записи, журнал на компьютере сам их забирает. Сервер ставится на виртуальную машину в казахстанском облаке (QazCloud, PS Cloud и т. п.) или позже на внутренний сервер КТО. Персональные данные (ФИО, ИИН, подписи) хранятся только на этой машине (ст. 12 Закона № 94-V).

## Что умеет

- Принимает записи в том же формате, что журнал v1.1 и приложение (`records` из .json). Закрытую запись изменить нельзя: другая версия той же закрытой записи не перезаписывает её, а попадает в список конфликтов для ОТОС.
- Роли:
  - **инструктирующий** отправляет свои записи и видит только их, загружает список персонала;
  - **инженер ОТОС** видит записи всех подразделений, загружает на сервер список персонала;
  - **администратор** заводит пользователей, выдает пароли, видит журнал действий.
- Вход по логину и паролю. Пароли хранятся только в виде хэша (scrypt). После 10 неверных паролей логин блокируется на 15 минут. Временный пароль от администратора при первом входе нужно сменить.
- Журнал действий: входы, новые и дополненные записи, конфликты, изменения пользователей.
- Резервная копия базы каждый день в 02:00 (время Казахстана), хранятся 30 дней.
- По одному адресу раздает: `/` приложение для телефона, `/journal/` журнал для компьютера, `/admin/` управление пользователями, `/ai/` тестовую страницу ИИ-помощника.
- ИИ-помощник для журнала: перед отправкой в ИИ заменяет ФИО и ИИН кодами, без ключа работает в тестовом режиме. Подробно: [ai/README.md](../ai/README.md).

Технически: Node.js 22 со встроенным SQLite; единственная сторонняя библиотека `@anthropic-ai/sdk` нужна только ИИ-помощнику. Caddy для HTTPS. Всё запускается через Docker Compose.

## Установка (1–2 часа, один раз)

### 1. Купить виртуальную машину в облаке РК

Подойдет самая простая: 2 ядра, 2–4 ГБ памяти, диск 40 ГБ, **Ubuntu 24.04** (или 22.04), публичный IP-адрес. При заказе укажите, что машина в дата-центре на территории Казахстана. Включите в панели облака ежедневные снимки (snapshot) диска, если они есть.

От облака вам нужны: **IP-адрес**, логин (обычно `root` или `ubuntu`) и пароль или ключ SSH.

### 2. Домен

Нужен адрес вида `journal.ваш-домен.kz`, который указывает на IP машины (DNS-запись типа **A**). Домен .kz можно купить у ps.kz, hoster.kz и др., там же в панели добавить запись A. Если у КТО есть свой домен, попросите ИТ добавить запись.

Для пробы без домена подойдет адрес `IP-с-дефисами.sslip.io`, например `85-29-10-20.sslip.io` для IP 85.29.10.20.

### 3. Поставить сервер

На компьютере с Windows откройте «Командную строку» и подключитесь к машине (адрес из шага 1):

```
ssh root@85.29.10.20
```

Затем на машине выполните по очереди (вместо `journal.example.kz` ваш домен):

```
apt-get update && apt-get install -y git
git clone https://github.com/aukeev/instruktazh-mobile.git
cd instruktazh-mobile/server
sudo sh install.sh journal.example.kz
```

Скрипт поставит Docker, запустит сервер, получит HTTPS-сертификат и в конце покажет **пароль администратора**. Запишите его.

### 4. Завести пользователей

1. Откройте `https://journal.example.kz/admin/`, войдите как `admin`, задайте свой пароль.
2. «Новый пользователь»: для каждого инструктирующего логин латиницей (например `ivanov.i`), ФИО, роль «Инструктирующий». Себе и коллегам по ОТОС роль «Инженер ОТОС».
3. Временный пароль показывается один раз. Передайте его лично.

### 5. Подключить журнал и телефоны

- **Журнал**: откройте `https://journal.example.kz/journal/` (или свой файл журнала v1.2) → «Архив и настройки» → «Общий сервер журнала» → адрес, логин, пароль → «Войти». Записи, которые уже есть в этом браузере, уйдут на сервер. Затем нажмите «Отправить список персонала на сервер», чтобы телефоны получили штатку.
- **Телефон**: откройте `https://journal.example.kz/` и добавьте на главный экран (или в прежнем приложении на GitHub Pages: ⚙ → «Общий сервер журнала»). Введите адрес, логин и пароль. Список персонала подтянется сам.

После этого закрытая запись уходит на сервер сразу после подписи инструктирующего. Если интернета нет, она ждет на телефоне и отправится сама, когда связь появится.

## Обслуживание

Все команды выполняются на машине в папке `instruktazh-mobile/server`.

| Что | Команда |
|---|---|
| Обновить программу после изменений в GitHub | `git pull && docker compose up -d --build` |
| Посмотреть, работает ли | `docker compose ps` |
| Посмотреть ошибки | `docker compose logs --tail 100 app` |
| Новый пароль администратору | `docker compose exec app node cli.js reset-password admin` |
| Резервная копия прямо сейчас | `docker compose exec app node cli.js backup` |

Резервные копии лежат в папке `server/backups` (файлы `journal-ДАТА.sqlite`). Раз в неделю копируйте свежую на другой носитель внутри КТО, например так с рабочего компьютера:

```
scp root@85.29.10.20:instruktazh-mobile/server/backups/journal-2026-12-01-02-00-00.sqlite .
```

Восстановление: остановить (`docker compose down`), положить копию вместо `server/data/journal.sqlite`, запустить (`docker compose up -d`).

## Что спросить у службы информационной безопасности

1. **Размещение**: можно ли держать ФИО, ИИН и подписи работников в облаке (назовите провайдера и дата-центр в РК) или только на внутреннем сервере КТО. Программа одинаково работает и там, и там.
2. **Доступ из интернета**: телефонам нужен доступ к серверу по HTTPS (порт 443) через мобильный интернет. Допустимо ли это, или сервер должен быть доступен только через VPN / внутреннюю сеть.
3. **Учетные записи**: устраивает ли вход по логину и паролю (пароль от 8 символов, блокировка после 10 ошибок, сессия 30 дней), или нужен вход через доменную учетную запись / ЭЦП.
4. **Резервные копии**: где хранить копии и сколько. Сейчас ежедневно, 30 дней, на той же машине; нужна вторая копия вне машины.
5. **Срок хранения журнала**: сколько лет хранить записи и кто вправе удалять. Сейчас удаление через программу не предусмотрено.
6. **Журнал действий**: достаточно ли журнала входов и изменений в самой программе, нужно ли передавать его в систему мониторинга (SIEM).
7. **Обработка ПДн**: нужно ли согласие работников на сбор и обработку ПДн в этой системе и включение её в перечень ПДн КТО.
8. **Сторонние сервисы**: подпись идет через SIGEX (sigex.kz, РК). HTTPS-сертификат выдает Let's Encrypt (на него уходит только имя домена). Код приложения лежит на GitHub (без данных).
9. **ИИ-помощник** (если включать с ключом): сервер обращается к api.anthropic.com (США) и отправляет только вопрос, обезличенные данные (коды вместо ФИО и ИИН, должность, участок, даты) и пункты Правил. Нужен ли для этого отдельный порядок согласования.

Сведения для ИБ: данные шифруются при передаче (HTTPS, TLS 1.2+). Файл базы на диске не шифруется программой; включите шифрование диска в облаке, если требуется. Сервер не проверяет криптографически подписи CMS при приеме: подлинность подписи проверяется на sigex.kz или в NCALayer по файлу .cms из журнала.

## API (для ИТ)

`POST /api/login` {login, password, newPassword?} → {token}; далее заголовок `Authorization: Bearer <token>`.
`GET /api/records?since=<rev>` → {rev, records}; `POST /api/records` {records:[...]} → {results:[{id, status: added|updated|same|conflict|forbidden|invalid}]}.
`POST /api/ai/chat` {question, history?, context?, demo?} → {answer, mode: claude|test, sent}; `GET /api/ai/status`.
`GET|PUT /api/staff`, `GET /api/conflicts`, `GET|POST /api/users`, `POST /api/users/update`, `GET /api/audit`, `POST /api/backup`, `GET /api/health`.

Проверка: `cd server && npm install && npm test`.
